# Web boundary audit supplement

## Purpose
Additional focused audit requested after the end-to-end review. No production logic, configuration or tests changed. Avoid treating every limit as a defect or adding rules before fixing demonstrated losses.

## New confirmed observations
1. Useful-content scoring penalizes structured facts. capabilities/builtins.py _web_evidence_substantive_characters drops every body line shorter than 20 characters. A complete small product table (model/memory, Alpha/16 GB, Beta/32 GB) scores 0, while a generic 90-character welcome sentence scores 90. This helper influences generation source ranking and candidate metadata; it is not itself a universal rejection gate. Evidence: work/verification/boundary-audit-probes.json. General impact includes names, lists, specifications and flattened table values.
2. Persistent web Evidence retains the processed snippet, not the fetched page representation. runtime/activities.py _result_evidence reads result results[].snippet and constructs WEB records with locator/content/hashes, confidence=1 and relevance=1. The runtime search result omits source_links at completion. Structured published_at/observed_at/source_links are not independent Evidence fields here; dates survive mainly as embedded text and retrieved_at is commit time. Full fetched content survives only when that call explicitly produced full content or the snippet retained it. Thus after provider truncation, later model recovery often cannot reconstruct the missing body without another fetch. Confidence=1 is bookkeeping, not proof that semantic truth was checked.
3. Structured-data source preference is not fully represented. _research_evidence_source_class maps WEB by publisher quality to official/editorial/user/general; it has no STRUCTURED_DATA output. A planner preference for structured data therefore cannot by itself prioritize a JSON result as structured data in this classifier. This is a code-path limitation, not evidence that every structured source is discarded.
4. Quality checks have unequal call paths. _answer_core_coverage_error is used by extractive envelope fallbacks; normal model-generated answers rely on citation integrity plus semantic review. Tests calling the helper directly do not prove it guards the normal model path. This does not justify wiring its topic regexes into every answer; the common assessment contract and production boundary tests need correction.
5. Not every candidate is newly generated by the model. _model_handler uses _invalid_web_envelope_fallback when generation time is unavailable or structured generation fails; that function can extract from role/document/forecast/general source handlers. Final quality review still runs. Existing topic-specific fallbacks are retained code and make the actual flow more complex than question-plus-evidence-only generation.

## Excluded or narrowed hypotheses
- Display-side loss is not demonstrated in the two retained weather outcomes. Re-running render_research_task_result on their actual stored Evidence exactly reproduces both saved answers (work/verification/render-boundary-replay.json). _normalize_web_analysis keeps raw answer as summary, and rendering starts from summary. No evidence here that a complete forecast was generated and the renderer deleted its rows. This is a server rendering replay, not a browser visual test.
- Preferred source classes do not universally delete unlisted sources: _apply_research_source_plan sorts preferred/fallback/other eligible classes; only wrong modalities or forbidden classes are removed. Do not call all preferences hard allowlists.
- source_links is present in the provider response and parsed into WebSearchResult for in-call coverage; its later omission from persisted result must not be misreported as an initial HTTP parsing failure.
- Normal model generation does receive the question and selected evidence. Failures can arise before that boundary, or within semantic review afterward.

## Root-cause priority after supplement
The strongest directly reproduced causes remain lexical pre-fetch deletion, unsafe document deduplication, needless content truncation, date-format-only exclusion and now short-record undervaluation. These are concrete local processing defects and should be fixed before expanding planning or retry machinery. Provenance/state improvements support diagnosis and recovery but are not a substitute for retaining the source facts in the first place.

No claim that all screenshots share one cause or all defects have now been found. This pass did not run another live model batch, modify existing test assertions, or execute release gates.
