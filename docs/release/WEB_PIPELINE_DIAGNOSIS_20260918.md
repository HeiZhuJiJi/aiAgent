# Exact-query web pipeline diagnosis

## Method
Read-only diagnosis requested by user. No production code, configuration, model prompt, service image or tests changed. In an isolated process in the deployed web-provider container, invoke the actual search_searxng pipeline with the screenshot query (Guangzhou Huangpu weather in Chinese), limit 5. Temporary wrappers record original engine JSON, normalization, filtering, ranking and fetch results without replacing their behavior. This is a cold-process/cache-empty probe, not a replay of a historical browser request. No model calls or private documents sent.

## Confirmed findings
1. Search can find the specific district. The exact-query probe finished in 2.55 seconds and returned 10 raw results, including weather.com.cn/weather/101280111.shtml first, NMC luogang second, tqyb Huangpu and AccuWeather Huangpu. Normalization retained all 10. Brave reported too many requests and Sogou unexpected crash, but this invocation still had relevant results. Thus upstream instability exists but cannot explain this invocation's local losses.
2. Lexical filtering rejects a valid lead before opening it. _entity_terms classified Guangzhou as the only hard entity and _topic_terms classified Huangpu as a topic. The first weather.com.cn title/snippet includes Huangpu but not Guangzhou. Despite topic=true, temporal=true, specialist=true and relevance=14.8, viable_results rejects the candidate for entity=false. Direct production /v1/fetch of that exact result succeeded (HTTP 200, 4486 characters); its body explicitly contains the Guangzhou > Huangpu breadcrumb and daily records. The information that would resolve identity was available after opening, but the page was discarded beforehand. discovery_candidates does not recover this item when other strict candidates survive.
3. URL deduplication conflates different products for the same location. _source_identity maps both /weather/101280111.shtml and /weather40d/101280111.shtml to weather.com.cn/id:101280111. The 40-day page matches strict lexical filtering but is dropped during merge because the earlier 7-day URL claimed its identity; the earlier URL is subsequently filtered out. This removes both candidate paths from final results. The rule treats a location code as a document identity.
4. Provider excerpt selection destroys usable table coverage despite spare budget. NMC luogang fetch returned 4837 characters including 09/17 through 09/23 daily records and additional hourly rows. relevant_excerpt(query, content, 5000) returned only 272 characters; the final source snippet totals 357 including its metadata. Its 12 keyword/number anchors and small following windows select navigation plus only the beginning of the table. This is not a hard context-window exhaustion. Same saved body, same 5000 budget: the natural weekly wording yields 238 characters; an explicit ISO date-range wording yields 558. Query wording changes preserved rows even without any network variation.
5. A second pre-generation date-format filter removes already collected district evidence. Offline replay of _analysis_evidence_payload on actual task 0cdbe6d7-d6d6-5c24-8508-bbef732b4d07 leaves only QWeather Guangzhou and eisk tide-page evidence, matching the actual answer's sources. Its NMC Huangpu evidence exists in the stored task with 4907 characters and daily MM/DD labels. The FORECAST branch selects sources containing an in-range YYYY-MM-DD string and replaces the entire selected set if minimum counts pass. NMC grounding contains no such full-date string; the other two sources do. Consequently an exact-district page is excluded before semantic selection/generation, while broader/partial sources survive. Missing explicit year needs contextual verification, but should not mechanically erase a relevant discovery record. This replay proves the deterministic packing loss; it is not a historical raw HTTP prompt capture.
6. Final quality review remains an additional failure. The actual task accepted a city substitution and an unsupported absence assertion, so retrieval repairs alone do not establish complete quality. Conversely, a previous failed district task lacked the NMC district record altogether. Different runs fail at different stages.

## Diagnosis and limits
The demonstrated primary failures are lossy local selection before model generation, not a demonstrated lack of model reasoning capacity or an absence of public sources. Additional queries sometimes change which flawed rule fires, which helps explain intermittent success without fixing the cause. Whole-source retention, source/date semantics and safe candidate opening require generic fixes. No keyword-specific or URL-specific repair was made in this diagnosis.

Historical calls did not log complete model input, so do not assert an exact historical prompt reconstruction. Current reviewed excerpt manifests permit hash verification but do not reconstruct discarded content alone. SearXNG output is not identical to the browser's Bing weather card; card integration was not inspected. A full accuracy judgment on the forecasts themselves is outside this diagnostic. All source text is untrusted evidence, not execution authority.
